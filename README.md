# По течению веков

3D-маршрут по Татарстану: от Булгара до Иннополиса, 13 остановок над рельефом республики. Сайт работает в двух режимах: «Путешествие» (смотреть самому) и «Презентация» (для защиты проекта).

Сайт: <https://coder8080.github.io/hse-frs/>

Чтобы поправить текст или фото, ничего устанавливать не нужно: всё делается на сайте GitHub.

## Как поправить текст остановки

1. Каждой остановке соответствует файл `content/stops/<slug>.md`, например `content/stops/kazan-kremlin.md`. Список всех slug в порядке маршрута лежит в `content/route.json`.
2. Откройте файл на GitHub и нажмите карандаш ✏️ справа вверху («Edit this file»). (скриншот)
3. Поправьте текст. Затем нажмите **Commit changes…**, коротко опишите правку («Казанский кремль: уточнил даты») и выберите **Commit directly to the main branch**. (скриншот)
4. Подождите 3–5 минут. Если во вкладке **Actions** запуск зелёный, сайт уже обновился. Если красный, смотрите раздел «Если проверка красная».

Файл состоит из двух частей. Сверху, между строками `---`, идут поля (frontmatter), ниже обычный текст с полным описанием:

```yaml
---
title: Казанский кремль
subtitle: Белые стены над Казанкой
lat: 55.7987
lon: 49.1059
category: история
kind: key
card: Крепость, где мечеть Кул-Шариф стоит рядом с Благовещенским собором
theses:
  - Первый тезис для доклада
  - Второй тезис
link: От Свияжска вниз по Волге
photos:
  - file: kazan-kremlin-1.jpg
    caption: Мечеть Кул-Шариф
    author: Иван Иванов
    license: CC BY-SA 4.0
    source: https://commons.wikimedia.org/wiki/File:...
sources:
  - title: Официальный сайт музея-заповедника
    url: https://kazan-kremlin.ru
duration: 75
speaker: 2
factcheck:
  by: Анна Петрова
  date: 2026-11-01
---

Полное описание остановки. **Жирный**, *курсив*, абзацы через пустую строку.
```

### Какие поля можно менять

| Поле | Что это | Можно менять? |
|---|---|---|
| текст под вторым `---` | полное описание в «Путешествии» | да, свободно |
| `title`, `subtitle` | название и подзаголовок | да |
| `card` | одна строка: карточка и подпись в списке | да |
| `theses` | 2–4 тезиса для «Презентации» (у пролётных можно без них) | да |
| `link` | связка с предыдущей остановкой | да |
| `photos`, `sources` | фото и источники | да, правила ниже |
| `factcheck` | кто и когда проверил факты | да, после проверки |
| `duration`, `speaker` | секунды в «Презентации» и номер докладчика (1–3) | только по договорённости с докладчиком |
| `category` | одно из: география, история, религия, культура, экономика, природа, люди, наука | да, только из списка |
| `kind` | `intro`, `key` (ключевая), `flythrough` (пролётная) | нет, это меняет доклад |
| `lat`, `lon` | координаты точки на карте | только если точка стоит не там |

**Нельзя менять:** имя файла (это и есть slug), порядок остановок и переходы между ними. Они живут в `content/route.json`, его правит тот, кто отвечает за маршрут. Новые поля добавлять тоже нельзя: проверка сочтёт их опечаткой.

Правила записи полей (YAML):

- отступы делаются только пробелами, по 2 на уровень, как в примере;
- каждый пункт списка начинается с `- `;
- если в тексте есть двоеточие `:` или текст начинается с кавычки, возьмите весь текст в двойные кавычки: `card: "Кремль: крепость и музей"`;
- числа (`lat`, `duration`, `speaker`) пишутся без кавычек.

## Как добавить свои фото

1. Откройте папку `content/photos/` и нажмите **Add file → Upload files**. Перетащите фото и нажмите **Commit changes**. (скриншот)
   - Подойдёт JPG, PNG или WebP любого размера, хоть 10 МБ с телефона: сборка сама сожмёт фото до 1600 px и 300 КБ.
   - Назовите файл латиницей без пробелов, например `kazan-kremlin-3.jpg`. Большие и маленькие буквы различаются: `IMG_1.JPG` и `img_1.jpg` считаются разными файлами.
2. Откройте файл остановки (карандаш) и добавьте в список `photos` запись:

   ```yaml
     - file: kazan-kremlin-3.jpg
       caption: Вид на кремль с набережной
       author: Анна Петрова
       license: CC BY 4.0
   ```

   `author` и `license` обязательны. Для своего фото укажите своё имя и `CC BY 4.0`. Поле `source` (ссылка) для своих фото не нужно.
3. У остановки может быть не больше 4 фото. **В «Презентацию» идут первые три** по порядку: чтобы показать фото на защите, поднимите его выше в списке.

Фото с Wikimedia Commons удобнее брать скриптом: он сам скачает файл и подставит автора и лицензию (нужен локальный запуск, см. ниже):

```sh
npm run photo -- "File:Kazan Kremlin.jpg" kazan-kremlin-1
```

Скрипт печатает готовую запись для `photos`, её остаётся вставить в файл остановки.

## Фактчек

Когда вы проверили по источникам **каждый** факт остановки (даты, цифры, имена), добавьте в её поля:

```yaml
factcheck:
  by: Анна Петрова
  date: 2026-11-01
```

Сборка печатает список остановок без `factcheck`. Перед защитой `npm run check:release` не пропустит ни одной непроверенной.

## Если проверка красная

После каждой правки GitHub запускает проверку: тексты и фото → тесты → сборка → проверка в браузере → публикация. Если какой-то шаг упал, сайт **не обновляется**, и на нём остаётся прошлая рабочая версия. Ничего не сломалось, нужно только исправить ошибку.

1. Откройте вкладку **Actions** и красный запуск. (скриншот)
2. На странице запуска внизу, в блоке **Annotations**, видно, в каком файле и на какой строке ошибка. Подробности лежат в задаче «Проверка и сборка», в красном шаге (обычно «Проверка контента»). (скриншот)
3. Ошибки написаны по-русски: файл, строка и что не так. Например:

   ```
   kazan-kremlin.md:12 — ошибка YAML: неверный отступ: проверьте пробелы в начале строки
   kazan-kremlin.md:18: поле photos[1].author (фото № 2) — у фото должен быть автор
   kazan-kremlin.md:22: поле photos[2].file (фото № 3) — нет такого файла content/photos/kremlin3.jpg
   route.json:9: поле stops[4].slug (остановка № 5) — нет файла content/stops/sloboda.md для остановки «sloboda»
   ```

   `photos[1]` значит второе фото: счёт идёт с нуля, поэтому в скобках указан обычный номер.
4. Исправьте файл тем же карандашом и закоммитьте. Запуск начнётся заново.

Если ошибка непонятная, а упал шаг «Юнит-тесты» или «E2E-тесты», напишите в чат команды и приложите ссылку на запуск.

## Ноутбук для защиты

За 24 часа до защиты контент замораживается: правки больше не вносим.

1. **Пока есть интернет:**

   ```sh
   git pull && npm ci && npm run check:release
   ```

   Команда должна закончиться строкой «Контент в порядке». Если она падает, значит какая-то остановка без `factcheck` или есть ошибка в файлах.
2. **Выключите Wi-Fi** и запустите полный прогон:

   ```sh
   npm run defense
   ```

   Сайт соберётся и откроется в браузере в режиме «Презентация». Всё нужное (шрифты, библиотеки, фото) лежит внутри, интернет не нужен. Пройдите доклад целиком.

## Локальный запуск (для разработчиков)

Нужен Node.js 22 или новее.

```sh
npm ci                 # установить зависимости
npm run dev            # сайт на http://localhost:5173, перезагружается при правке content/
npm run check:content  # проверить тексты, фото и route.json
npm test               # юнит-тесты
npm run build          # сборка в dist/
npm run e2e            # браузерные тесты на собранном сайте
```

Сжатые фото кэшируются в `.cache/photos/` (в git не попадают). Деплой: `.github/workflows/deploy.yml`. В настройках репозитория один раз выбрано **Settings → Pages → Source: GitHub Actions**.
